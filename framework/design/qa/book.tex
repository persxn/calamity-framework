\chapter{Containers from first principles}\label{ch:one}
\section{Why containers exist}
A \term{container} is a process with its own view of the system. Run \cmd{docker run --rm -it debian:12}; the
file \file{/etc/hosts} and the flag \flag{--network=host} stay literal. See \cref{ex:ns}.
\begin{definition}{namespace}A kernel feature that gives a process its own view of one resource.\end{definition}
\begin{keyidea}[the one thing]A container is not a small VM.\end{keyidea}
\begin{plainwords}It is a fenced-off process.\end{plainwords}
\begin{underthehood}\code{clone(CLONE_NEWPID)} makes the new PID namespace.\end{underthehood}
\begin{designnote}Layers are content-addressed so they can be shared.\end{designnote}
\begin{gotcha}\code{COPY .env} bakes secrets into a layer.\end{gotcha}
\begin{misconception}Containers are secure by default.\end{misconception}
\begin{origin}chroot, 1979.\end{origin}
\begin{scale}One registry serves billions of pulls.\end{scale}
\begin{vocab}Image, layer, registry, digest.\end{vocab}
\begin{outage}A full disk of dangling layers.\end{outage}
\begin{aiwatch}The model suggested \flag{--privileged}.\end{aiwatch}

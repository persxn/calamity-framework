# Calamity 2.0.0

Calamity 2.0 turns the 1.0 tutor into a full learning system: mastery paced
by evidence, GATE and competitive programming carried through practice,
mocks and contests, a developer track with drills and projects, a career
layer, one design system for every document, and the framework installable
as a Claude Code plugin. It runs on your own Claude account: no API keys,
tokens or secrets.

## Install

- **As a plugin**: inside Claude Code,
  `/plugin install calamity --marketplace persxn/calamity-framework`, then open
  Claude Code in an empty folder for your record and type `/onboard`.
- **As a clone**: `git clone https://github.com/persxn/calamity-framework.git`,
  then `python3 engine/calamity.py doctor` and `/onboard` (README, "Installation").
- **From 1.x**: `docs/migrating-to-2.0.md`.

## What is new

**Mastery by evidence.** A topic is secured by a second item at least 20
minutes after the first, and unlocks what builds on it only then; at most
two topics are open per skill (three on the GATE tracks). Objectives are tagged by strand (theory,
practice, implementation, numericals) and coverage counts toward `solid`
and `mastered`. The daily quota adapts to the review load and first-try
accuracy, and says why. Teaching is recorded with its parts and pace, and
the learner model and n-of-1 experiments (`model`, `experiment`) feed a
weekly review by the `learning-analyst`.

**GATE.** Practice sets from books and previous papers with revisits,
numerical-answer tracking, revision passes, lecture revision, backdated
course ticks, revision packs (formula sheet and error book), deepened
syllabi, and mock scouting (`career list --kind gate-mock`).

**Competitive programming.** The cp program: phases toward the rating
target, monthly checkpoints, band measures, recognition practice, and judge
sets from CSES, USACO and AtCoder.

**Developer track.** Six drill types (debug, docs-only debug, code reading,
AI-output audit, prompt specs, chaos) written by the `drill-smith` and
verified blind; integration projects between skills; the frontier of what
to learn next; session types (system day, classic, outage study, open
source, vocabulary); `codebase-reading` and `ai-pair-engineering`.

**Sessions.** `/day` runs the day block by block; six hooks (the brief, the
key guard, request routing and `!feedback`, the Stop guard, compaction,
session end); `mastery-coach` on the engine; a task queue in the brief;
date-wise history and a monthly journal.

**Career.** Opportunity records with sources and terms, readiness computed
from the record, the application pipeline, nudges that respect a blackout
(GATE's final phase or a date you set), an evidence-only portfolio, the
`career-advisor`, and `/career`. Sites that forbid automated access are
paste only.

**Calamity Paper.** One design system from `framework/design/tokens.json`
(Charter, Fira Sans, Fira Mono, Charter maths): `calamity.sty` for notes,
books and one-page cheat sheets, `calamity.css` for `dash --html`, an SVG
palette and terminal schemes. Built and checked on Tectonic and TeX Live
(pdfLaTeX, XeLaTeX, LuaLaTeX).

**The plugin.** `bin/calamity` on the shell's PATH, `hooks/hooks.json`, a
`learner_dir` setting, the tutor's output style carrying the rules, and
`setup --permissions`. Every skill and agent now writes `calamity <command>`.
In a clone, `setup --shim` adds the command and `setup --alias` the shell
function (alone: Claude Code with permission prompts off; with a command:
the engine).

**Checks.** Branch protection with one required check (`ci-ok`), CI on
Linux, macOS and Windows for Python 3.9 to 3.15, `claude plugin validate
--strict`, an end-to-end run and a fuzzer, and fourteen behaviour evals run
locally on your own account (`tools/evals.py`).

The CHANGELOG lists every change.

## Known limits

- The Windows `calamity.cmd` and a marketplace install on a second machine
  have not been tried yet.
- Notes and cheat sheets report LaTeX errors and page overflow; only study
  books have the full page check.
- Release evals (one Sonnet run each, judge Sonnet): 13 of 14 passed on the
  first run. `resume-bullets-trace-to-evidence` failed once on explanatory
  clauses its judge counted as additions, and passed on the rerun: a
  borderline case to watch.

# LaTeX conventions

The house style lives in `mastery-book.sty`. Use its macros and environments instead of ad-hoc formatting, so the whole book stays consistent and the checks can understand it.

## File layout

```
book-root/
├── main.tex              # parts, \include per chapter, solutions appendix, bibliography
├── mastery-book.sty      # house style (copied from the template; edit only to fix style bugs)
├── refs.bib
├── book-state.md         # chapters ↔ units, edition, build and review status, changelog
├── benchmark.md          # bestseller benchmark for this topic (review.md, part C)
├── frontmatter/preface.tex
├── chapters/ch01-<slug>.tex, ch02-<slug>.tex …
├── solutions/ch01.tex …
├── figures/src/*.svg     # sources (edit these)
├── figures/build/*.pdf   # generated by build.sh — keep them (Overleaf needs them)
└── build/                # main.pdf, logs, pages/*.png, figpreview/*.png, check-report.md
```

In `main.tex`: one `\part{}` per curriculum part, `\include{chapters/chNN-slug}` per chapter, and `\input{solutions/chNN}` inside the solutions appendix.

## Labels

Prefix every label: `ch:`, `sec:`, `fig:`, `tab:`, `lst:`, `ex:`. Refer with `\cref{}` (it writes "Figure 1.2", "Exercise 3.4"), or with `\Cref{}` at the start of a sentence.

## Callout boxes

Each takes an optional subtitle: `\begin{gotcha}[Sorting needs everything first] … \end{gotcha}`.

| Environment | Use for |
|---|---|
| `origin` | History and the designers' story |
| `plainwords` | The plain-language version of an idea, just before its precise definition |
| `definition{term}` | The precise definition (the term is a required argument) |
| `keyidea` | The one sentence to remember from a section |
| `underthehood` | The deepest mechanism detail; optional on first read |
| `designnote` | Why it's built this way; rejected alternatives |
| `tryit` | Something the reader runs now |
| `gotcha` | A trap and why it happens |
| `misconception` | A common wrong belief, and the correction |
| `interview` | An interview question and what a strong answer contains |
| `outage` | A real incident: the decision, the chain, the lesson (cited) |
| `aiwatch` | A typical AI-tool mistake in this area and how to catch it |
| `scale` | How a large company does this (cited) |

Use boxes for what they mean, not for decoration. More than about three boxes per page reads as clutter. Keep the core explanation in the prose.

## Inline technical text

- `\cmd{ls -la --block-size=K}` for commands, `\flag{--si}` for flags, `\file{/etc/passwd}` for paths. These keep `--`, `_` and `#` literal; the style disables the `--` → dash ligature in typewriter text, and the build check verifies that long flags print literally.
- A `%` can't go inside these macros. Use `\lstinline|printf("%d")|` instead.
- `\term{inode}` for the first use of a vocabulary term: italic, and indexed.
- `\key{Ctrl}+\key{C}` for keys.

## Code and terminal output

```latex
\begin{shell}
$ ls -la /tmp | head -3
total 48
drwxrwxrwt 12 root root 4096 Oct 25 17:02 .
\end{shell}

\begin{code}[language=C]
int *p = &x;
\end{code}
```

- Prompt lines start with `$ ` (they're highlighted); output lines have no prompt.
- **Use real output** captured from the tool. Mark trimmed output with `...` on its own line and say so in the text.
- Keep lines under about 80 characters. Listings wrap long lines, but wrapped output is hard to read, so trim or reformat instead.
- Avoid raw Unicode inside listings (box-drawing characters, emoji, curly quotes): pdflatex can't render it. Replace it, or describe it.
- Put long listings that need a caption in `\begin{lstlisting}[caption={...},label={lst:...}]`.

## Tables

Use booktabs only: `\toprule`, `\midrule`, `\bottomrule`, with no vertical rules. Put the caption above the table.

- Flag and option tables use `tabularx` with an `X` description column, at `\linewidth` (see `assets/example`).
- An exhaustive table that may span pages uses `longtable`, with `\endhead` repeating the header row.
- Group rows by purpose (a group column, or `\midrule` between groups) instead of listing flags alphabetically.
- Keep cell text short. If a cell needs a paragraph, that entry belongs in the prose after the table.

## Figures

Use `\svgfigure[width]{name}{caption}{fig:label}`. The source is `figures/src/name.svg`; `build.sh` produces `figures/build/name.pdf`. The default width is `0.92\linewidth`; pass a smaller width for simple figures. A missing build prints a red MISSING FIGURE placeholder and fails the check. Captions say *what to notice*, not just what the figure is.

## Exercises and solutions

```latex
\chapterexercises
\begin{exercise}[3]{ex:ls-hang}     % [difficulty 1–4]{required label}
...
\end{exercise}

% solutions/chNN.tex
\section*{Chapter~\ref{ch:ls}}
\begin{solution}{ex:ls-hang}
...
\end{solution}
```

## Chapter-end sections

Use `\chaptersummary`, `\chaptervocab` (with `\begin{vocablist} \item[Term] definition \end{vocablist}`), `\chapterexercises` and `\furtherreading`. These are unnumbered sections that still appear in the table of contents.

## Escaping in normal text

`\_  \%  \#  \&  \$  \{  \}  \textasciitilde{}  \textasciicircum{}  \textbackslash{}`. Prefer `\cmd{}` for anything code-like, so you don't have to escape. For arrows and symbols use math: `$\rightarrow$`, `$\le$`, `$\times$`. Use `` `` '' `` for quotes, never `"`.

## Things that break builds

- An `@` in a comment in `refs.bib` (BibTeX ignores `%` and parses it as an entry).
- A `%` inside `\cmd{}`, or an unbalanced brace inside it.
- Raw Unicode in listings.
- A `\label` before `\caption` in floats (the reference goes to the wrong number). In `\svgfigure` the order is already correct.
